# タグの正規化仕様

## 目的

タグの内部キーと表示名を分離し、Neon、管理画面、検索・絞り込みで同じ意味のタグを同じ値として扱います。アプリケーションで利用する既知の内部キーと標準表示名は `packages/shared/src/tag-definitions.json` を正とします。

## DB構成

| テーブル           | 役割                                            |
| ------------------ | ----------------------------------------------- |
| `tags`             | UUIDの `id` と、一意な言語非依存の `key` を保存 |
| `tag_translations` | タグIDとロケールごとの表示名を保存              |
| `pub_tags`         | 店舗IDとタグIDの多対多関係を保存                |

`tag_translations` の主キーは `(tag_id, locale)`、表示名の一意制約は `(locale, name)` です。`pub_tags` の主キーは `(pub_id, tag_id)` で、同じ店舗への同一タグの重複を防ぎます。タグを削除すると翻訳と店舗関係もカスケード削除されます。

## タグ定義のSource of Truth

既知の内部キーと標準表示名は、[`packages/shared/src/tag-definitions.json`](../../packages/shared/src/tag-definitions.json)だけで管理します。この文書や他の仕様書にタグ一覧を複製せず、一覧を変更するときはJSONと、その定義を利用するテスト・実装を同じ変更で更新します。

## 正規化ルール

- 前後の空白を除去し、Unicode NFKCと大文字小文字を正規化します。
- 空白またはアンダースコアはハイフンへ変換し、連続するハイフンを1つにします。
- `tag-definitions.json` の `aliases` に定義した別名を対応する内部キーへ変換します。
- 定義にないタグは表記だけを正規化して保持し、意味を推測して統合しません。
- 店舗内では正規化後の内部キーを重複排除します。
- 未知のタグに選択ロケールの表示名がない場合、画面では内部キーを表示できます。

## 読み書き

Repositoryは取得時に `pub_tags`、`tags`、`tag_translations` を結合し、内部キーの配列と表示名の対応表を生成します。要求ロケールの翻訳がない場合は日本語（`ja`）へフォールバックします。

作成・更新時は、正規化した内部キーを `tags.key` へUPSERTし、日本語の標準表示名を `tag_translations` へUPSERTした後、`pub_tags` に店舗との関係を保存します。店舗から外されたタグとの関係は削除しますが、タグの親レコードと翻訳は自動削除しません。

検索フィルターも共有の正規化処理を通すため、入力表記が異なっても同じ内部キーで照合します。利用店舗数はNeonの `pub_tags` を集計して確認します。

## 管理画面からのタグ管理

`/admin/tags` では内部キーと日英表示名を分離して登録・編集し、`pub_tags` から使用店舗数を表示します。管理入力の契約、transaction、削除拒否は[管理タグ仕様](tag-management.md)を参照してください。

使用中タグはUIとAPIの両方で削除を拒否します。DBのCASCADEだけに依存せず、タグ行をロックして店舗関連がない場合だけ条件付きDELETEします。現在の店舗フォームではカンマ区切り入力をRepositoryで正規化してタグを自動生成します。タグ選択UIは未導入です。
