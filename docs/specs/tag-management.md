# 管理タグ仕様

## 目的

`/admin/tags` でタグの内部キー、日本語・英語表示名、使用店舗数を管理します。店舗とタグの関連付けは本機能では変更せず、`pub_tags` から参照中のタグを誤って削除しないことを優先します。

## 管理モデル

```ts
type AdminTag = {
  id: string;
  key: string;
  nameJa: string;
  nameEn: string | null;
  pubCount: number;
};
```

- `id` はDBのUUIDです。
- `key` は言語非依存の識別子で、作成後は変更できません。
- 日本語表示名は必須です。
- 英語表示名は任意です。空欄で更新すると `locale = 'en'` の翻訳レコードを削除します。
- `pubCount` は `pub_tags.pub_id` の重複を除いた件数です。

## 入力契約

| 項目     | 必須       | 最大長 | 検証・保存                                                                     |
| -------- | ---------- | ------ | ------------------------------------------------------------------------------ |
| `key`    | 作成時のみ | 64     | `^[a-z0-9]+(?:-[a-z0-9]+)*$`。前後空白、大文字、連続・先頭・末尾ハイフンを拒否 |
| `nameJa` | 必須       | 100    | 前後空白を除去。空文字を拒否                                                   |
| `nameEn` | 任意       | 100    | 前後空白を除去。空文字は未登録として保存                                       |

共有Validationは `packages/shared/src/admin-tag.ts` を正とし、ブラウザのHTML Validationは操作支援、API側Validationを最終判断とします。`tags.key` と `(tag_translations.locale, tag_translations.name)` のUNIQUE制約は競合時の最終防衛線です。

## 保存と削除

登録ではアプリケーションでUUIDを先に生成し、`tags`、日本語翻訳、入力がある場合の英語翻訳を非対話型transactionへまとめます。更新では日本語翻訳のUPSERTと、英語翻訳のUPSERTまたはDELETEを同じtransactionへまとめます。

削除では次の順序を単一transactionで実行します。

1. 対象 `tags` 行を `FOR UPDATE` でロックする。
2. `pub_tags` の使用件数を取得する。
3. `pub_tags` が存在しない場合だけ、`NOT EXISTS` 付きの条件で `tags` を削除する。
4. 使用中の場合は `409` とし、`tags`、`tag_translations`、`pub_tags`、`pubs` を変更しない。

DBではタグ削除時に翻訳と店舗関連がCASCADEされますが、管理機能は使用中タグのDELETE自体を実行しません。未使用タグを削除した場合だけ、対応する翻訳がCASCADEで削除されます。

## APIとセキュリティ

管理タグAPIは署名済み管理セッションを要求します。`POST`、`PATCH`、`DELETE` はリクエスト先と完全一致する `Origin` を要求し、JSON本文を持つ処理は `Content-Type: application/json` を要求します。

主なステータスは、入力不正 `422`、未認証 `401`、Origin不正 `403`、重複・使用中 `409`、対象なし `404`、DB未設定 `503`、内部エラー `500` です。DB・SQL・接続情報はレスポンスへ含めません。

## UI状態

- 保存・削除中はフォームと操作ボタンを無効化し、二重送信を防ぎます。
- 成功は `role=status`、失敗は `role=alert` で通知します。
- 使用店舗数が1件以上の削除ボタンは無効化し、理由を表示します。
- 未使用タグの削除前には、元に戻せない操作であることを確認します。
- `DATABASE_URL` 未設定時は一覧を空で表示し、変更操作を無効化します。

## 後続Issueとの境界

店舗フォームのカンマ区切り入力とRepositoryによるタグ自動生成は、店舗フォームをタグ選択UIへ変更する後続Issueまで維持します。本機能では店舗へのタグ付与・解除、タグkey変更、使用中タグの強制削除・一括置換を行いません。
